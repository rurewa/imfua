# Идеи для следующего руководства по индексам

Вы уже освоили базовое руководство: `SHOW INDEX`, `EXPLAIN`, `CREATE INDEX`, составные и покрывающие индексы, влияние функций в `WHERE`. Следующий шаг — углубиться в одну из специализированных тем. Вот несколько вариантов с разной степенью сложности.

---

## 1. Полнотекстовый поиск (`FULLTEXT`) и индексы

**Для чего:** поиск по словам в текстовых полях (`LIKE '%слово%'` не использует индекс, а `FULLTEXT` — использует).

**Что будет в руководстве:**
- Создание `FULLTEXT`-индекса.
- `MATCH(col) AGAINST('слово')` — синтаксис.
- Разница между `IN NATURAL LANGUAGE MODE` и `IN BOOLEAN MODE`.
- Почему `LIKE '%текст%'` плохо, а `FULLTEXT` — хорошо.
- Ограничения `FULLTEXT` в InnoDB (минимальная длина слова, стоп-слова).

**Практика:** таблица `articles` с текстами, поиск по ключевым словам.

---

## 2. Индексы для `ORDER BY` и `GROUP BY`

**Для чего:** понять, как индексы ускоряют сортировку и группировку, и почему `Using filesort` — это плохо.

**Что будет в руководстве:**
- Индекс и `ORDER BY` — когда сортировка не нужна.
- `ORDER BY` по нескольким столбцам и составной индекс.
- `GROUP BY` и покрывающий индекс.
- Почему `ORDER BY RAND()` — убийца производительности.
- Как переписать запрос, чтобы убрать `Using filesort`.

**Практика:** `EXPLAIN` для `ORDER BY` и `GROUP BY` до и после создания индексов.

---

## 3. Индексы и `JOIN`: оптимизация соединений

**Для чего:** `JOIN` — самая частая причина медленных запросов.

**Что будет в руководстве:**
- Индексы на внешних ключах (автоматически создаются, но не всегда).
- `EXPLAIN` для `JOIN` — порядок соединения таблиц.
- `type: eq_ref` vs `ref` vs `ALL` в `JOIN`.
- Составные индексы для `JOIN` + `WHERE`.
- Почему `LEFT JOIN` может быть медленнее `INNER JOIN`.

**Практика:** две-три таблицы, `EXPLAIN` до и после добавления индексов на столбцы соединения.

---

## 4. Мониторинг и анализ неиспользуемых индексов

**Для чего:** индексы замедляют запись. Нужно уметь находить «лишние» индексы.

**Что будет в руководстве:**
- `sys.schema_unused_indexes` — какие индексы не использовались.
- `sys.schema_redundant_indexes` — дублирующиеся индексы.
- `performance_schema.table_io_waits_summary_by_index_usage` — статистика использования.
- Как безопасно удалить неиспользуемый индекс.
- Размер индексов: `mysql.innodb_index_stats`.

**Практика:** создать несколько индексов, часть из них не использовать, найти их через `sys`.

---

## 5. Индексы в MySQL 8.0: новые возможности

**Для чего:** MySQL 8.0 добавил много нового, что не описано в базовом руководстве.

**Что будет в руководстве:**
- **Невидимые индексы** (`INVISIBLE`) — индекс есть, но оптимизатор его не использует. Удобно для тестирования.
- **Гистограммы** (`ANALYZE TABLE ... UPDATE HISTOGRAM`) — помогают оптимизатору при неравномерном распределении данных.
- **Функциональные индексы** (`CREATE INDEX idx ON t ((LOWER(name)))`) — индексирование выражений.
- **Индексы на JSON-поля** (`CAST(json_col->>'$.name' AS CHAR(100))`).
- **`EXPLAIN ANALYZE`** — реальное время выполнения.

**Практика:** сравнить `EXPLAIN` с невидимым индексом и без него, создать функциональный индекс.

## 6. Индексы и производительность записи (`INSERT`/`UPDATE`/`DELETE`)

**Для чего:** понять цену индексов при изменении данных.

**Что будет в руководстве:**
- Сколько времени добавляет каждый индекс к `INSERT`.
- Почему `UPDATE` индексированного столбца дороже.
- Как массовые вставки (`INSERT ... VALUES (...), (...)`) взаимодействуют с индексами.
- `LOAD DATA INFILE` и отключение индексов на время загрузки.
- Баланс между скоростью чтения и записи.

**Практика:** замер времени `INSERT` 1000 строк с индексами и без.

## 7. Префиксные индексы и индексы для `LIKE`

**Для чего:** индексировать длинные строки без создания огромного индекса.

**Что будет в руководстве:**
- `CREATE INDEX idx ON t (col(10))` — индекс по первым 10 символам.
- Когда префиксный индекс работает, а когда нет.
- `LIKE 'prefix%'` — использует индекс, `LIKE '%суффикс'` — нет.
- Как выбрать длину префикса.
- Полнотекстовый поиск как альтернатива для `LIKE '%...%'`.

**Практика:** таблица с длинными URL/email, сравнение `EXPLAIN` с полным и префиксным индексом.

---

## 8. Индексы и партиционирование

**Для чего:** для очень больших таблиц (миллионы строк) партиционирование + индексы дают выигрыш.

**Что будет в руководстве:**
- `PARTITION BY RANGE`, `LIST`, `HASH`.
- Как индексы работают с партициями.
- `EXPLAIN` и `partitions` в выводе.
- Когда партиционирование помогает, а когда — нет.
- Ограничения: внешние ключи, уникальные индексы.

**Практика:** таблица с партициями по году, `EXPLAIN` для запроса с фильтром по году.

## 9. Кластеризованные и некластеризованные индексы (глубоко)

**Для чего:** понять физику хранения InnoDB.

**Что будет в руководстве:**
- Как устроен `.ibd`-файл.
- Кластеризованный индекс по PK — физическая сортировка строк.
- Вторичные индексы и «двойной поиск» (index lookup + row lookup).
- Почему `AUTO_INCREMENT` лучше `UUID` для PK.
- `SHOW INDEX` и `Cardinality` — что это.

**Практика:** сравнить `.ibd`-файлы для таблиц с `AUTO_INCREMENT` и `UUID` PK.
