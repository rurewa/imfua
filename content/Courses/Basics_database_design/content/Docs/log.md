## Запись лога действий в БД

Чтобы записать все команды, выполняемые в базе данных **MySQL**, нужно включить один из её встроенных журналов. Для вашей задачи (полная запись всех действий) лучше всего подходит **General Query Log** (общий журнал запросов). Он фиксирует каждое полученное сервером SQL-выражение и каждое подключение клиента.

### 📝 Шаг 1: Включение журнала в работающем контейнере

Самый быстрый способ — включить журнал прямо сейчас, не перезапуская контейнер. Для этого нужно выполнить SQL-команду внутри вашего контейнера `my-mysql`.

Выполните в терминале:
```bash
docker exec -it my-mysql mysql -uroot -p123 -e "SET GLOBAL general_log = 'ON';"
```

Чтобы убедиться, что журнал включился, и узнать, куда он пишется, выполните:
```bash
docker exec -it my-mysql mysql -uroot -p123 -e "SHOW VARIABLES LIKE 'general_log%';"
```

Вы увидите что-то вроде этого:

```
+------------------+------------------------------+
| Variable_name    | Value                        |
+------------------+------------------------------+
| general_log      | ON                           |
| general_log_file | /var/lib/mysql/... .log      |
+------------------+------------------------------+
```

**Важно:** Путь к файлу журнала (`general_log_file`) находится **внутри** контейнера. Чтобы прочитать его с вашего компьютера, используйте команду `docker exec`:

```bash
# Замените имя файла на то, что увидели в предыдущем шаге
docker exec my-mysql cat /var/lib/mysql/имя_вашего_хоста.log
```

### ⚙️ Шаг 2: Постоянное включение (рекомендуется)

Команда `SET GLOBAL` включает журнал только до перезапуска контейнера. Чтобы он включался автоматически, нужно добавить настройки в ваш файл `my.cnf`, который вы монтируете в контейнер.

1. Откройте ваш файл `my.cnf` (он находится в той же папке, откуда вы запускали контейнер).
2. Добавьте в секцию `[mysqld]` следующие строки:

    ```ini
    [mysqld]
    # ... ваши существующие настройки ...
    general_log = 1
    general_log_file = /var/lib/mysql/general.log
    ```

3. Перезапустите контейнер, чтобы применить изменения:

    ```bash
    docker restart my-mysql
    ```

Теперь все команды будут записываться в файл `general.log` внутри контейнера автоматически.

Проверить, что лог пишется
```shell
docker exec my-mysql ls -la /var/lib/mysql/general.log
```
заглянуть в него:
```shell
docker exec my-mysql cat /var/lib/mysql/general.log
```
забрать лог на хост
```shell
docker cp my-mysql:/var/lib/mysql/general.log ./general.log
```
Очистка лога внутри контейнера
```shell
docker exec my-mysql sh -c ': > /var/lib/mysql/general.log'
```

### 📂 Альтернативы и важные нюансы

*   **Запись в таблицу**: Вместо файла MySQL может писать журнал в специальную таблицу `mysql.general_log`. Это может быть удобнее для анализа через SQL-запросы. Включить это можно так:
    ```sql
    SET GLOBAL log_output = 'TABLE';
    SET GLOBAL general_log = 'ON';
    ```
    После этого читайте журнал так: `SELECT * FROM mysql.general_log;`

*   **Другие типы журналов**: Не путайте `General Query Log` с другими журналами, которые решают иные задачи:
    *   **Binary Log**: Записывает только команды, **изменяющие данные** (`INSERT`, `UPDATE`, `DELETE`), и используется для репликации и восстановления. Его можно просмотреть утилитой `mysqlbinlog`.
    *   **Slow Query Log**: Записывает только те запросы, выполнение которых заняло больше заданного времени. Полезен для поиска проблем с производительностью, но не для полного аудита.

*   **Влияние на производительность**: `General Query Log` создаёт значительную нагрузку и может быстро занять много дискового пространства. **Обязательно выключайте его**, когда он не нужен для отладки, с помощью команды `SET GLOBAL general_log = 'OFF';`.

### 💎 Итог

Для полной записи всех команд используйте **General Query Log**. Проще всего включить его на время сессии командой `SET GLOBAL general_log = 'ON';`. Для постоянного использования добавьте `general_log = 1` в ваш `my.cnf`. Не забывайте отключать этот журнал после завершения отладки, так как он сильно нагружает систему.
