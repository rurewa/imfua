Движок (storage engine) — это ключевой компонент MySQL, который определяет, **как именно физически хранятся данные, индексируются, блокируются и обрабатываются** внутри таблицы. Одна база данных может содержать таблицы с разными движками, и выбор движка для каждой таблицы — важное архитектурное решение.

---

### 🗂️ Основные движки MySQL и их назначение

#### 🟢 InnoDB — стандарт для современных приложений
**InnoDB** является движком по умолчанию начиная с MySQL 5.5, и в MySQL 8.0 он безраздельно доминирует, включая все системные таблицы.

*   **Ключевые особенности**: Полная поддержка **ACID-транзакций** (атомарность, согласованность, изоляция, долговечность), **внешних ключей** (`FOREIGN KEY`) и **блокировок на уровне строк**. Это позволяет множеству пользователей одновременно читать и изменять разные строки одной таблицы без блокировки друг друга.
*   **Для чего лучше всего**: Идеален для **OLTP-систем** (онлайн-транзакции), где важна целостность данных и высокая конкурентная нагрузка (интернет-магазины, банковские системы, учётные приложения).

#### 🟡 MyISAM — устаревший движок для чтения
**MyISAM** был движком по умолчанию до MySQL 5.5. В MySQL 8.0 он **не рекомендуется к использованию для новых проектов**, хотя технически всё ещё доступен. MyISAM не поддерживает транзакции и внешние ключи.

*   **Ключевые особенности**: Использует **блокировки на уровне всей таблицы** (при записи блокируется вся таблица, что мешает параллельному чтению). Данные хранятся в трёх файлах (`.frm` — структура, `.MYD` — данные, `.MYI` — индексы). Поддерживает полнотекстовый поиск.
*   **Для чего лучше всего**: Подходит для **read-only** или преимущественно читаемых нагрузок, например, в хранилищах данных (Data Warehouse), где данные редко обновляются. **Не подходит** для приложений с частой записью из-за блокировок таблицы.

#### 🔵 MEMORY — сверхбыстрые временные данные
Этот движок хранит все данные в оперативной памяти (RAM), обеспечивая очень быстрый доступ.

*   **Ключевые особенности**: Данные **теряются при перезапуске сервера**. Поддерживает хеш-индексы (для точного поиска) и B-tree индексы. Не поддерживает транзакции и внешние ключи.
*   **Для чего лучше всего**: Для временных таблиц, кэшей, сессионных данных или промежуточных вычислений, где скорость важнее долговечности.

#### 🗜️ ARCHIVE — компактное хранилище
Предназначен для хранения больших объёмов **архивных или исторических данных**, которые редко запрашиваются.

*   **Ключевые особенности**: Данные **сжимаются** и не индексируются. Поддерживаются только операции `INSERT` и `SELECT`; обновление и удаление невозможны.
*   **Для чего лучше всего**: Для долгосрочного хранения логов, аудиторских записей или старых транзакций, к которым нет частого доступа.

#### 📄 Другие специализированные движки
*   **CSV**: Хранит данные в виде обычных текстовых файлов с разделителями-запятыми. Удобен для **обмена данными** с электронными таблицами и скриптами, но не поддерживает индексы.
*   **BLACKHOLE**: Принимает данные, но **ничего не сохраняет** (как `/dev/null`). Используется в каскадной репликации для передачи данных без хранения на промежуточном сервере.
*   **FEDERATED**: Позволяет создать таблицу, которая **физически находится на удалённом сервере MySQL**. Удобно для создания распределённых систем или витрин данных (datamart).
*   **NDB (NDBCLUSTER)**: Кластерный движок для систем с требованиями к **высокой доступности и отказоустойчивости** (распределённые базы данных).

### 📊 Сравнение ключевых характеристик

| Характеристика | **InnoDB** | **MyISAM** | **MEMORY** | **ARCHIVE** |
| :--- | :--- | :--- | :--- | :--- |
| **Транзакции (ACID)** | ✅ Да | ❌ Нет | ❌ Нет | ❌ Нет |
| **Внешние ключи (FK)** | ✅ Да | ❌ Нет | ❌ Нет | ❌ Нет |
| **Блокировка** | На уровне строк | На уровне таблицы | На уровне таблицы | На уровне строк |
| **Хранение** | Диск (табличные пространства) | Диск (3 файла на таблицу) | Память (RAM) | Диск (сжатый) |
| **Индексы** | B-tree, кластерный, полнотекст. | B-tree, полнотекст. | Хеш, B-tree | Нет |
| **Сжатие данных** | ✅ Да | ✅ Да (через утилиты) | ❌ Нет | ✅ Да (всегда) |
| **Основное назначение** | OLTP, конкурентная запись | Чтение, Data Warehouse | Временные/кэш-данные | Архивы, логи |

### 🛠️ Как работать с движками в вашем Docker-контейнере

**1. Посмотреть доступные движки:**
```sql
SHOW ENGINES;
```
В столбце `Support` значение `DEFAULT` указывает на движок по умолчанию (в MySQL 8.0 это будет `InnoDB`).

**2. Посмотреть движок конкретной таблицы:**
```sql
SHOW TABLE STATUS LIKE 'имя_таблицы';
```
Или через `information_schema`:
```sql
SELECT TABLE_NAME, ENGINE FROM information_schema.TABLES WHERE TABLE_SCHEMA = 'имя_базы';
```

**3. Создать таблицу с определённым движком:**
```sql
CREATE TABLE my_memory_table (
    id INT PRIMARY KEY,
    data VARCHAR(100)
) ENGINE = MEMORY;
```

**4. Сменить движок существующей таблицы:**
```sql
ALTER TABLE имя_таблицы ENGINE = InnoDB;
```
⚠️ **Важно**: Смена движка — ресурсоёмкая операция, которая перестраивает таблицу и блокирует её на время выполнения. На больших таблицах это может занять много времени.

---

### 💎 Итог: что выбрать?

Для подавляющего большинства задач современной разработки правильный выбор — **InnoDB**. Он обеспечивает целостность данных, конкурентный доступ и надёжность. **MyISAM** стоит рассматривать только для очень специфичных сценариев с преимущественно читаемой нагрузкой и отсутствием требований к транзакциям. Специализированные движки (`MEMORY`, `ARCHIVE`, `CSV`) решают узкие задачи и не подходят для основных бизнес-данных.

Если хотите, можем на практике в вашем контейнере создать таблицы с разными движками и сравнить их поведение при конкурентной записи или перезапуске сервера.
