Ошибка `Required property is missing: jobs` означает, что YAML-парсер **не видит корневой ключ `jobs:`**. Скорее всего, при редактировании файла:

- строка `jobs:` была случайно удалена, или
- `jobs:` получила отступ (должна быть на нулевом уровне), или
- в файл попал **таб** вместо пробелов (YAML запрещает табы для отступов), или
- `build-packages:` оказался на нулевом уровне (вне `jobs:`).

Проще всего — заменить файл целиком на проверенный.

## ⚠️ Частая причина ошибки — табы

Если при редактировании в редакторе включена автозамена пробелов на табы (или наоборот, вы копировали из веб-интерфейса), YAML ломается. Проверьте файл на наличие табов:

```bash
grep -P '\t' .github/workflows/ci.yml
```

Если что-то выведется — там табы, их нужно заменить на пробелы. Проще всего перезаписать файл целиком (например, через `nano` или `micro`, где можно включить отображение табов) и вставить текст выше.

Проверить структуру верхнего уровня можно так:

```bash
head -20 .github/workflows/ci.yml
```

Должно быть ровно так, без отступов у `name:`, `on:`, `jobs:`:

```
name: Hex Loader CI/CD

on:
  push:
    ...
  pull_request:
  workflow_dispatch:

concurrency:
  ...

jobs:
  test:
  ...
```

## 🔍 Как проверить YAML локально

Чтобы не гонять CI ради проверки синтаксиса, можно проверить YAML локально:

```bash
# через Python (обычно есть в системе)
python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo OK
```

Если `OK` — синтаксис валиден. Если ошибка — покажет строку и колонку.

После пуша GitHub перечитает `ci.yml` и, если YAML валиден, кнопка **Run workflow** появится, а job `test` запустится на пуше.
